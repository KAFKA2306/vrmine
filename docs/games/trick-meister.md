# RULEFORGE — ルール可変トリックテイキング

## 位置づけ

`RULEFORGE` は、Friedemann Friese作『Stich-Meister / トリックマイスター』の「毎ラウンド、プレイヤーがルールカードを選び、トリックのルールを変更する」という構造を実装する非公式VRChatゲームです。原作の名称をワールド内タイトルに使用せず、カード画像、ロゴ、説明書本文も収録しません。

参照情報:

- SUNNY BIRD（日本語版出版社）: https://sunny-bird.com/information/new_products/1965/
- SUNNY BIRD 出版タイトル一覧: https://sunny-bird.com/wholesale/
- BoardGameGeek製品情報: https://boardgamegeek.com/boardgame/81250/stich-meister
- 英語ルール翻訳: https://spotlightongames.com/rules/stichmeister.html

## 人数と目的

- 3–5人。
- プレイヤー人数と同じラウンド数を行う。
- 全ラウンド終了時、合計点が最大の席が勝者。

## カード

- プレイカード60枚: 4スート × 1–15。
- 3人戦では各スートの1、10、13を除外し、48枚を16枚ずつ配る。
- ルールカード60枚。各プレイヤーは3枚保持する。

## ラウンド

1. 各席がルールカードを1枚選ぶ。
2. 3人戦では山札から1枚を追加する。
3. 5人戦ではディーラー左隣の席はルールカードを出さない。
4. 選ばれた最大4枚を番号順に適用する。
5. 必要な準備処理を行う。
6. ディーラー左隣からトリックを開始する。
7. 手札終了または選択ルールの終了条件までトリックを繰り返す。
8. トリック点と追加得点ルールを計算する。
9. ディーラーを左へ移し、次ラウンドへ進む。

## 通常時のトリック

- 最初に出されたカードのスートをフォローする。
- フォロー可能なら、同じスートを出さなければならない。
- 切り札があれば切り札が非切り札に勝つ。
- 同条件では数字が大きいカードが勝つ。
- 通常は獲得した各トリックが1点。

## 操作

1. instance masterが`3P`、`4P`、`5P`のいずれかを選ぶ。人数変更時は既存席と進行状態を初期化する。
2. 各プレイヤーが有効な`SEAT`を1つ選ぶ。
3. 選択人数の全席が埋まると、自動で配札して開始する。
4. 表示された3枚の`RULE`から1枚を選ぶ。
5. 準備フェーズがある場合は必要枚数をマークし、`CONFIRM`する。
6. 自分の手番に手札カードを選ぶ。出されたカードは中央の5枠へ同期表示される。
7. 全ラウンド終了まで繰り返す。

人数変更とresetはinstance masterだけが実行でき、実行前にゲームmanagerと同期stateのownershipを取得します。退室者の席はmaster側の`TrickSeatLifecycle`が解放し、別プレイヤーが同じ席へ参加できます。

## ルール26の表示

ルール26が有効な場合、各トリックの1枚目だけを公開し、2枚目以降は中央表示で`FACE DOWN`とします。全員が出し終えた時点で全カードを公開し、確認時間後にトリックを解決します。

同期配列には実カード値が保持されるため、この秘匿は通常クライアントのUI上の保証です。改造クライアントに対する秘密情報保護ではありません。

## ルールカード実装

全60番号のコード上の挙動は [trick-meister-rules.md](trick-meister-rules.md) に明示しています。

## 既知の適合性制約

- ルール21、34、39、40などは原版説明書との逐語的照合を完了していません。リンク先の実装表は「現ワールドが実行する規則」であり、原版の完全な翻刻ではありません。
- 各プレイヤーの手札は表示上は本人だけに出しますが、`BoardState.playerHands`がUdon同期変数であるため、改造クライアントに対する秘匿性は保証できません。
- 全60ルールを個別の固定入力で網羅するG2テストは未完成です。

この制約が解消されるまでは「原作完全再現」または「全60ルール完全検証済み」と表示しません。
