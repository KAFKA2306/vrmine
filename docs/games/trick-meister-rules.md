# Rule Card Implementation Matrix

この表は `GameController.cs` の現行コードが実行する挙動です。原版ルールカード本文の転載ではありません。

## Trump rules 1–21

| No. | 実装挙動 |
|---:|---|
| 1–14 | ルール番号+1の数字を切り札にする。1→数字2、14→数字15。 |
| 15 | Coinスートを切り札にする。 |
| 16 | Fanスートを切り札にする。 |
| 17 | Koiスートを切り札にする。 |
| 18 | 数字1を切り札にする。 |
| 19 | 数字1・10・13を切り札にする。 |
| 20 | Gateスートを切り札にする。 |
| 21 | 第2トリック以降、現在のトリックのリードスートを切り札として扱う。 |

複数の切り札条件に一致するカードは、一致数が多いほど強い。同数なら、より小さいルール番号に一致するカードを優先する。

## Basic rules 22–40

| No. | 実装挙動 |
|---:|---|
| 22 | 各席が3枚を選び、左隣へ渡す。 |
| 23 | 各席が3枚を選び、右隣へ渡す。 |
| 24 | 各席が1枚を選び、ラウンド中の手札から除外して予約する。 |
| 25 | 選択したカードを公開情報として記録する。選択枚数は現コード上3枚。 |
| 26 | 各トリックの1枚目だけ表向きに表示し、2枚目以降を伏せて出す。全員が出した後に全カードを公開し、短い確認時間後に勝者を判定する。 |
| 27 | リードカードではなく、直前に出されたカードをフォロー対象にする。 |
| 28 | フォローできず切り札を持つ場合、切り札を出す義務がある。 |
| 29 | 通常判定でリードカードが勝つ場合、そのカードを除いた中の最強カードを勝者にする。 |
| 30 | 通常判定の2番目に強いカードを勝者にする。 |
| 31 | 同条件では数字が小さいカードを強くする。 |
| 32 | 非切り札を切り札より強くする。 |
| 33 | 非切り札同士の比較でリードスート優先を無効にし、数字で比較する。 |
| 34 | 各トリックの最初のカードを獲得者なしとして得点対象から除外する。 |
| 35 | トリック勝者の右隣がカードとトリック数を獲得する。 |
| 36 | トリック勝者の左隣が次のリードを行う。 |
| 37 | 奇数番号のトリックでは進行方向を反転する。 |
| 38 | 3トリック終了後、各席が3枚を選び右隣へ渡す。 |
| 39 | ラウンド終了時、最終トリック勝者が獲得した全カード・トリック数を右隣へ移す。 |
| 40 | 各席に3枚残った時点でラウンドを終了し、得点条件用の獲得トリック数に3を加算する。 |

## Verification requirement

ルール番号の説明と実装の一致は、コードレビューだけでは動作保証になりません。`GameController.VerifyRules()` に各番号の固定入力テストを追加し、全60番号がPASSするまでは「60ルール完全検証済み」と表記しません。現状の自己テストは配札、フォロー、低数字優先、複合切り札、ルール26の伏せ表示と公開フェーズを検査します。
